  1. `apps/backend/tests/test_url_ingest.py::MimeTypePickerTests::test_octet_stream_triggers_filename_fallback`
     — asserts `_pick_mime_type("application/octet-stream", "/audio.flac") ==

     `mimetypes.guess_type('/audio.flac')` → `('audio/x-flac', None)`.

     boundary implication, but it is a real failing test. Either the test
     should accept the `audio/x-flac` / `audio/flac` pair, or
     `apps/backend/url_ingest.py::_pick_mime_type` should normalize the
     `x-flac` form before returning. No auto-fix per task instructions.

## Phase boundary audit

Goal: confirm Phase 2 / Phase 3 code never mutates Phase 1 results, never
re-computes a value already in the Phase 1 schema, and never assigns to
Phase 1-authoritative fields (loudness, tonal balance, dynamics, stereo
image, spectral centroid/rolloff).

### Phase 2 (`apps/backend/server_phase2.py`)

  1. `_build_phase2_prompt` / `_build_stem_summary_prompt` / `_build_descriptor_hooks`
     — read `measurement_result` exclusively via `.get(...)`. The
     descriptor-hook record is a new dict; the original phase1 payload is
     untouched. No mutation.
  2. `_normalize_measurement_result_for_gemini` (`server_phase2.py:742`)
     constructs `normalized = dict(payload)` and replaces
     `spectralDetail` with the output of
     `server_phase1._normalize_spectral_detail`, which itself does
     `out = dict(detail)` before any `.pop()` / rename. The original
     `measurement_result` dict and its nested `spectralDetail` are *not*
     mutated. ✅ shallow-copy boundary is intact.
  3. `_finalize_style_profile_authoritative_measurements`
     (`server_phase2.py:2352`) reads `measurement_result.get("bpm" | "key" |
     "timeSignature")` and writes them onto the Phase 2
     `styleProfile.authoritativeMeasurements`. This is a **defense** of the
     invariant (Phase 1 overrides Phase 2's claim), not a violation. ✅
  4. `_sanitize_optional_phase2_fields` (`server_phase2.py:1416`) — `.pop()`
     calls are on a copy of the **Phase 2** result (`sanitized = dict(data)`),
     not Phase 1.

  No Phase 2 code path writes to a Phase 1 field, replaces a Phase 1
  measurement, or re-computes loudness / spectral / stereo / dynamics
  metrics.

### Phase 3 (`apps/backend/sample_*.py`, `server_samples.py`)

  1. `server_samples.py::_extract_phase1_from_snapshot` returns the
     measurement result by reference; downstream callers treat it as
     read-only.
  2. `sample_generation.py::generate_samples_plan` reads `phase1` exclusively
     via the local `_safe_get(payload, key)` helper (line 346), which is a
     pure `dict.get(...)` wrapper. Every consumer
     (`kickDetail.fundamentalHz`, `kickDetail.decayTimeMs`, `key`,
     `keyConfidence`, `bpm`, `bassDetail`, `melodyDetail`) is read-only.
  3. `sample_theory.py::build_context` accepts the relevant Phase 1 values as
     **scalars** (`key`, `bpm`, `key_confidence`), not the phase1 dict — so it
     structurally cannot mutate Phase 1.
  4. `sample_synthesis.py` and `sample_drums.py` operate on synthesis
     primitives (frequency, decay, sample-rate) — they have no reference to
     phase1.

  No Phase 3 module rewrites a Phase 1 field or re-derives a Phase 1 metric.

## Needs human review

  1. **`test_octet_stream_triggers_filename_fallback`** — is the canonical
     contract `audio/flac` (test correct, `_pick_mime_type` should
     normalize) or `audio/x-flac` (test should accept both)? `audio/x-flac`
     is what stdlib emits on Python 3.11.15 on macOS arm64; on other
     platforms / installs this test may pass. Pinning the expected value to
     whatever the production deployment serves is the right fix; needs a
     human to make that call.
